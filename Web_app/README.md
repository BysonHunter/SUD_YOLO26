# SUD YOLO26 · Web

Веб-приложение для загрузки DICOM-архива, подготовки проекций, детекции YOLO26, расчёта параметров камней, интерактивного просмотра и скачивания PDF. Работает рядом с [настольным приложением](../Application/), используя его вычислительные модули и обученную модель. Код настольного приложения не изменён.

Быстрые переходы: [пользователи и пароли](#пользователи-и-пароли),
[сброс и восстановление](#сброс-и-восстановление-пароля),
[настройка Яндекс Почты](#отправка-через-яндекс-почту),
[обновление сервера](#обновление-существующего-сервера),
[проверка и решение проблем](#проверка-почты-и-решение-проблем).

## Быстрый запуск через Docker

Нужен **весь репозиторий**, включая [Application/src](../Application/src/) и [веса](../Application/weights/kidney_yolo26.pt). Копирования только этой папки недостаточно. Обучающий датасет и каталоги пациентов серверу не нужны.

Установите Docker Engine с Compose v2 на Linux либо Docker Desktop с Linux-контейнерами на Windows. Для первого запуска потребуется Интернет для загрузки образов и Python-пакетов. Для обработки одного большого исследования предусмотрено до 12 ГиБ RAM на worker; хосту желательно иметь 16–32 ГиБ RAM и запас диска от 30 ГиБ. Каждая дополнительная копия worker увеличивает потребление памяти.

В терминале перейдите в эту папку:

```powershell
cd C:\WorkDOCS\PROJECTS\SUD_YOLO26\Web_app
python configure.py
docker compose up -d --build
docker compose ps
```

В Linux используются те же команды после перехода в `Web_app`. Скрипт [configure.py](./configure.py) создаёт `.env` со случайными паролями; существующий файл не заменяет. Для него нужен Python 3.11 или новее. Если Python на сервере отсутствует, создайте `.env` на другом компьютере и перенесите его отдельно по защищённому каналу.

Откройте **http://localhost:8080**. Логин `admin`, начальный пароль — значение `SUD_BOOTSTRAP_PASSWORD` в локальном `.env`. После смены пароля используйте свой новый пароль: повторная инициализация сервера его не сбрасывает. Не публикуйте этот файл. Начальная конфигурация привязана к `127.0.0.1`, работает по HTTP и предназначена для локальной проверки. Пароли, DICOM, результаты и рабочие окружения исключены из Git и контекста сборки Docker.

Также работает **http://127.0.0.1:8080**: локальные имена `localhost` и `127.0.0.1` допускаются на одном порту и с одним протоколом. Сторонние сайты и другие порты не допускаются. Порт `8086` использовался только при разработке и для обычного запуска не нужен. В поле пароля вводится само значение после `SUD_BOOTSTRAP_PASSWORD=`, а не имя этой переменной.

Проверить конфигурацию без вывода секретов:

```powershell
docker compose config --quiet
docker compose logs --tail=100 worker
```

Не прикладывайте полный вывод `docker compose config` или журналы заданий к публичным обращениям: они могут содержать секреты или идентификаторы пациентов.

### Светлая и тёмная темы

На странице входа и в верхней части рабочего пространства есть кнопка
**«Светлая тема» / «Тёмная тема»**. Надпись обозначает тему, на которую можно
переключиться. По умолчанию включена тёмная тема с синим фоном и бирюзовыми
акцентами. Выбор сохраняется в текущем браузере и применяется после обновления
страницы и при следующих входах. Для других браузеров, компьютеров и настольного
приложения тема выбирается отдельно. Если сохранение данных сайта отключено,
переключатель продолжает работать в открытой вкладке, но выбор может не сохраниться.

Оформление меняется и в диалогах регистрации, паролей и управления пользователями,
а также в интерактивной 3D-модели. Открытое исследование и положение камеры 3D
сохраняются. Цвета режимов лазера, HU, снимки КТ и сохранённые PNG/PDF тема не меняет.
После обновления сервера перезагрузите страницу, чтобы загрузить новый переключатель.

### Пользователи и пароли

Войдите под `admin` и откройте **«Пользователи»** в левом меню. В форме создания
укажите логин (3–80 латинских букв, цифр или символов `_.@-`, первый символ — буква
или цифра) и пароль (12–128 символов). Логин сохраняется в нижнем регистре.
Кнопка **«Создать пользователя»** добавляет обычную учётную запись без прав
администратора. Пароль передайте пользователю лично; система не показывает
сохранённые пароли и их хеши. Также доступна самостоятельная регистрация на странице входа.

В таблице показаны логин, email, роль, статус и число исследований. Кнопка **«Удалить»**
открывает подтверждение с логином выбранного пользователя. После подтверждения
пользователь исчезает из списка, вход запрещается, все сеансы закрываются.
Исследования и их результаты сохраняются на сервере с прежним владельцем;
выполняющиеся задания могут завершиться. Удалённый логин зарезервирован и не
передаёт данные новой учётной записи. Самого `admin` удалить нельзя. Обычные
пользователи не видят этот раздел и не имеют доступа к его API.

Каждый пользователь, включая `admin`, может нажать **«Сменить пароль»** в нижней
части левого меню. Укажите текущий пароль, новый и его повтор. После сохранения
текущий сеанс обновляется, остальные сеансы этой учётной записи закрываются.
Новый пароль хранится в БД как хеш scrypt с индивидуальной солью и сохраняется
после перезапуска контейнеров. Открытые пароли в БД не записываются.

### Сброс и восстановление пароля

У администратора в разделе **«Пользователи»** есть кнопка **«Email / сброс пароля»**.
Откройте карточку пользователя: здесь можно сохранить или исправить email и нажать
**«Сбросить пароль»**. Это завершает все его сеансы и закрывает доступ со старым
паролем. В таблице появляется статус **«Требуется новый пароль»**. Данные и
исследования пользователя сохраняются. Администратор не видит его пароль.

Если настроена почта, одноразовая ссылка отправляется на сохранённый email.
Администратору также показывается ссылка для личной передачи пользователю по
защищённому каналу — это позволяет восстановить доступ старой учётной записи без
email или при сбое почтовой отправки. Ссылка действует **30 минут**, повторный сброс
отменяет предыдущую. Смена email также отменяет ранее выданные ссылки. Не
передавайте ссылку другим людям и не публикуйте её. Для `admin` доступно изменение
собственного email; сброс своей учётной записи этой кнопкой запрещён, чтобы
случайно не заблокировать администратора.

При попытке входа с правильным старым паролем после административного сброса
система предложит восстановить доступ. Это предложение не даёт доступа к
исследованиям: новый пароль можно установить только по одноразовой ссылке.
Зная один логин, сменить чужой пароль нельзя.

Если пароль забыт, на странице входа нажмите **«Забыли пароль?»**, укажите email,
ранее сохранённый в учётной записи, и откройте ссылку из письма. Задайте и повторите
новый пароль (12–128 символов, отличный от предыдущего), затем войдите с ним.
После сохранения все старые сеансы и ссылки восстановления прекращают действовать.
Сам запрос письма пароль не изменяет и сеансы не завершает. Ответ на запрос
одинаковый для существующих и неизвестных адресов; действуют ограничения частоты.
При отсутствии письма проверьте «Спам» и обратитесь к администратору. Отправка
выполняется фоновой задачей API; при перезапуске во время отправки или ошибке SMTP
письмо может не прийти — запросите новую ссылку позже.

В БД хранятся только SHA-256 хеши случайных токенов. Сам токен передаётся в
фрагменте ссылки `#reset=…` (не в HTTP GET), удаляется из адресной строки при
открытии формы и отправляется серверу только при сохранении нового пароля.
Текущие и новые пароли по email не отправляются.

### Отправка через Яндекс Почту

1. В [настройках Яндекс Почты](https://mail.yandex.ru/?pdd_domain=#setup/client)
   разрешите доступ почтовым программам и использование паролей приложений.
2. В [Яндекс ID → Пароли приложений](https://id.yandex.ru/security/app-passwords)
   создайте пароль типа **«Почта»**, например с названием `SUD YOLO26`.
   Нужен пароль приложения, а не обычный пароль аккаунта. См.
   [официальную инструкцию](https://yandex.ru/support/yandex-360/customers/mail/ru/mail-clients/others).
3. Из каталога `Web_app` выполните `python configure_mail.py` (из обычного
   интерактивного терминала, не перенаправляя ввод). Укажите полный
   email отправителя и пароль приложения. Пароль вводится скрыто и сохраняется
   только в локальном `.env`, исключённом из Git и сборки Docker. Скрипт не меняет
   пароли пользователей или БД. Не вставляйте секрет в командную строку.
4. Проверьте `SUD_PUBLIC_ORIGIN`: это адрес сайта, доступный получателям писем.
   Для локальной проверки допустим `http://localhost:8080`; для удалённых
   пользователей нужен действующий HTTPS-адрес без пути, например
   `https://sud.example.org`, и `SUD_SECURE_COOKIE=true`. Ссылка с `localhost`
   не откроет сервер с другого компьютера.
5. После обновления приложения выполните `docker compose up -d --build`.
   После одной лишь смены почтовых настроек достаточно `docker compose up -d --no-deps api`.
   Проверьте восстановление на своей тестовой учётной записи с доступным email.

Почтовые переменные: `SUD_SMTP_HOST=smtp.yandex.ru`, `SUD_SMTP_PORT=465`,
`SUD_SMTP_USER` (полный email), `SUD_SMTP_PASSWORD` (пароль приложения),
`SUD_MAIL_FROM` (тот же email). Порт 465 использует TLS с проверкой сертификата;
также поддерживается 587 с обязательным STARTTLS. Другие порты не разрешены.
Настройки передаются только сервису API, вычислительному worker они не нужны.
Без настроенной почты форма восстановления честно сообщает об этом; сброс с
личной передачей одноразовой ссылки администратором продолжает работать при
корректном `SUD_PUBLIC_ORIGIN`. Приложение не подключается к входящей почте.

### Обновление существующего сервера

Сохраните резервные копии БД PostgreSQL, тома `studies` и локального `.env` по
правилам вашего сервера. Само обновление не заменяет `.env`, пароли пользователей
или результаты. Из корня клонированного репозитория выполните:

```powershell
git pull --ff-only
cd Web_app
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

Сервис `initialize` автоматически добавляет поля и таблицу восстановления в БД.
После обновления перезагрузите страницу браузера. Для настройки отправки на новом
сервере отдельно выполните `python configure_mail.py` и примените настройки:

```powershell
docker compose up -d --no-deps api
```

Скрипт `configure.py` нужен только при первой установке: существующий `.env` он не
перезаписывает. Почтовые реквизиты с GitHub не загружаются: на каждом сервере их
задают локально. При переносе существующей системы переносите её тома и настройки
отдельно, сохраняя владельцев и права. Не используйте `docker compose down -v`
для обновления: этот параметр удаляет тома с данными.

### Проверка почты и решение проблем

1. Войдите под `admin`, создайте тестовую учётную запись с email, к которому у вас
   есть доступ, либо зарегистрируйте такую запись на странице входа. Адрес должен
   быть уникальным в системе. Сохранённый email виден в таблице пользователей.
2. Выйдите и нажмите **«Забыли пароль?»**. Укажите этот email, дождитесь письма,
   откройте ссылку, задайте новый пароль и войдите с ним. Запрос письма сам по себе
   не меняет пароль. Не проверяйте отправку на чужих адресах.
3. Для проверки административного сброса откройте карточку того же тестового
   пользователя и нажмите **«Сбросить пароль»**. После сброса старый пароль не
   должен давать доступа, а новая одноразовая ссылка должна позволять задать новый.

| Ситуация | Что проверить |
| --- | --- |
| «Восстановление по email пока не настроено» | Запустите `configure_mail.py`, проверьте `SUD_PUBLIC_ORIGIN`, затем пересоздайте API указанной выше командой. |
| Письмо не пришло | Проверьте «Спам», сохранённый email и настройки почтовых программ Яндекса. Нужен действующий пароль приложения «Почта». Посмотрите журнал API: `docker compose logs --tail=50 api`. Сообщение `Password recovery email could not be delivered` указывает на ошибку отправки. |
| После нескольких запросов письма перестали приходить | На email действует лимит 5 запросов в час, на прямой IP сервера — 30 в час. Публичный ответ намеренно одинаковый; повторите позже. За reverse proxy дополнительно настройте ограничения по реальному IP клиента. |
| Ссылка недействительна | Ссылка действует 30 минут и используется один раз. Используйте последнее письмо: новый запрос, административный сброс и изменение email или пароля отменяют прежние ссылки. |
| Ссылка открывает не тот компьютер | Исправьте `SUD_PUBLIC_ORIGIN` на внешний HTTPS-адрес сайта, перезапустите API и запросите новую ссылку. `localhost` подходит только для просмотра на компьютере сервера. |
| У пользователя нет email | Администратор может сохранить его в карточке. До настройки почты администратор также может передать полученную после сброса одноразовую ссылку лично. |
| Администратор забыл пароль и email не настроен | На сервере выполните `docker compose exec api python -m sudweb.manage password admin`. Пароль вводится скрыто; существующие сеансы и ссылки восстановления отменяются. |

Не публикуйте полный вывод `docker compose config`, содержимое `.env` и ссылки
восстановления. Для проверки наличия настроек без вывода почтового пароля можно
выполнить:

```powershell
docker compose exec api python -c "from sudweb.config import Settings; from sudweb.recovery import mail_ready; print(mail_ready(Settings.from_env()))"
```

`True` означает, что обязательные настройки заполнены. Это не проверка соединения
с SMTP или доставки письма; их проверяет описанный выше сценарий восстановления.

Обновление схемы существующей БД выполняет команда `python -m sudweb.manage init`;
при запуске Compose её автоматически выполняет сервис `initialize`. Данные
пользователей и исследований при обновлении не переносятся и не удаляются.

### Все исследования, удаление и архив администратора

У `admin` раздел **«Исследования»** показывает исследования **всех пользователей**,
включая удалённые учётные записи. На каждой карточке указан владелец. Поле
«Владелец» фильтрует список по логину; переключатель позволяет оставить текущие,
удалённые пользователем или архивные записи. Сначала загружается 100 карточек,
остальные доступны по кнопке **«Показать ещё»**; фильтры действуют на загруженные
карточки. Администратор открывает изображения, 3D, параметры и PDF любого владельца.

У обычного пользователя **«Удалить»** скрывает исследование из списка и закрывает
доступ ко всем его изображениям, моделям и отчётам. Администратор продолжает видеть
его со статусом **«Удалено пользователем»** и исходной стадией обработки. Файлы
сохраняются. Уже запущенная обработка может завершиться; скрытие не отменяет её.
Скрытие не освобождает дисковую квоту — для этого нужно архивирование администратором.

Кнопка администратора **«Удалить результаты → в архив»** доступна после завершения
или отмены обработки. Исходный `input.zip` сначала копируется в
`/data/archives/<UUID владельца>/<UUID исследования>/input.zip`, проверяется по
SHA-256, затем удаляется рабочий каталог с распакованными DICOM, изображениями,
моделями и PDF. Запись БД с владельцем, исходным именем и датами остаётся со статусом
**«В архиве»**. При ошибке копирования или проверки результаты не удаляются;
операцию можно повторить. Если загрузка не была завершена, принятого исходного
ZIP может не быть — кнопок скачивания и повторного анализа у такой записи нет.

Только администратору доступны **«Скачать исходный ZIP»** и **«Повторить анализ»**.
Повторный анализ создаёт отдельное исследование, принадлежащее `admin`, с указанием
UUID источника, и запускает обычную очередь обработки. Исходная запись и её
владелец сохраняются, удалённое исследование не возвращается пользователю.
Кнопки окончательного уничтожения архивного ZIP нет; архив хранится до отдельного
решения администратора о сроках хранения. Архив занимает место на томе `studies`
и входит в его резервную копию; пользовательская квота на него не распространяется.

### Шифрование загружаемого ZIP

Браузер автоматически шифрует содержимое ZIP **перед отправкой**. Используются
Web Crypto API, отдельный случайный AES-256 ключ на загрузку и AES-GCM с тегом
128 бит для каждого блока размером до 1 МиБ. IV блока состоит из случайного
64-битного префикса и 32-битного номера блока; AAD связывает блок с UUID задания,
полным размером файла и номером блока. AES-ключ передаётся только обёрнутым
RSA-OAEP/SHA-256; закрытый RSA-3072 ключ остаётся на сервере в
`/data/transport/private.pem` с ограниченными правами доступа. При нескольких API
используется общий ключ из того же постоянного тома. Не удаляйте ключ во время загрузок.

Сервер принимает только последовательные аутентифицированные блоки, проверяет
длину и целостность, расшифровывает их в приватный `upload.part`. Только после
получения всех блоков и завершения загрузки создаётся `input.zip`, а задание
попадает в очередь распаковки и анализа. Незашифрованная загрузка ZIP через API
не принимается. В памяти браузера находится один блок, а не весь архив.
Сбой соединения требует новой загрузки; автоматического продолжения нет.
Для незавершённой карточки доступна **«Отменить»**, после чего администратор может
удалить её рабочие файлы. Имя ZIP и размер передаются в служебных метаданных.

При доступе с другого компьютера **обязателен HTTPS с доверенным сертификатом**:
он защищает логин/пароль, cookie и подлинность ключа сервера. Клиентское шифрование
не заменяет TLS. HTTP допускается браузером только для локального
`localhost`/`127.0.0.1`; для обычного сетевого HTTP загрузка блокируется без перехода
к незашифрованной передаче. Это требование [Web Crypto API](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/encrypt).
На сервере рабочие и архивные ZIP хранятся **расшифрованными**, в закрытом томе;
шифрование диска или резервных копий настраивается отдельно.

После обновления установите зависимости из [requirements.txt](./requirements.txt)
или пересоберите контейнеры: `docker compose up -d --build`. Сервис `initialize`
добавит поля удаления, архивирования и шифрованной загрузки в существующую БД
без удаления исследований. Обновите страницу браузера перед следующей загрузкой.

### Самостоятельная регистрация

На странице входа нажмите **«Первый вход? Создать учётную запись»**. Укажите имя
пользователя (будущий логин), email, пароль и повтор пароля; отметьте согласие на
обработку персональных данных. После создания войдите по логину и заданному паролю.
Для самой регистрации SMTP не нужен; принадлежность почтового адреса при
регистрации не подтверждается. Сохранённый email используется для восстановления
пароля после настройки SMTP. Пароль можно сменить после входа.

Логины и email уникальны, регистр не учитывается. Занятые логин/email, в том числе
принадлежащие удалённому пользователю, повторно использовать нельзя. Совпадение
проверяется сервером, уникальность дополнительно обеспечивает БД при одновременных
регистрациях. Имя `admin` зарезервировано. Самостоятельная регистрация всегда
создаёт обычного пользователя, без прав администратора. Email виден администратору
в списке пользователей; другим пользователям он не выдаётся.

Согласие не отмечено заранее. Сервер сохраняет время, точный принятый текст,
версию (SHA-256 текста и URL политики) и URL политики вместе с учётной записью.
Без согласия или при устаревшей версии текста регистрация отклоняется. Для текущей
формы предусмотрено до пяти попыток регистрации в час на прямой IP; при работе
за proxy дополнительно настройте ограничитель на нём.

Настройки в локальном `.env`:

```dotenv
SUD_REGISTRATION_ENABLED=true
SUD_PRIVACY_POLICY_URL=https://your-organization.example/privacy
SUD_CONSENT_TEXT=Текст согласия, утверждённый оператором вашей системы
```

URL политики при указании должен быть HTTPS. По умолчанию используется короткий
технический текст о согласии на обработку имени и email для обслуживания аккаунта.
Перед публичным размещением замените его текстом вашего оператора и укажите
действующую политику; эти настройки не являются юридической экспертизой согласия.
`SUD_REGISTRATION_ENABLED=false` отключает самостоятельную регистрацию, сохраняя
создание аккаунтов администратором. После изменения настроек выполните
`docker compose up -d`. Существующий `.env` скриптом настройки не перезаписывается.

### NVIDIA GPU

Для Linux нужен драйвер NVIDIA и NVIDIA Container Toolkit. Для Windows используется поддержка GPU Docker Desktop/WSL2. Проверка внутри контейнера обязательна; наличие видеокарты на хосте само по себе не подтверждает её доступность контейнеру. RTX 3090 поддерживает используемую сборку PyTorch с CUDA 12.8 при подходящем драйвере.

```powershell
docker compose -f compose.yaml -f compose.gpu.yaml up -d --build
docker compose -f compose.yaml -f compose.gpu.yaml exec worker python -c "import torch; print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0))"
```

Описание настроек GPU: [документация Docker](https://docs.docker.com/compose/how-tos/gpu-support/). Оставляйте **один worker на одну GPU**, пока не измерены VRAM и время обработки. GPU ускоряет детекцию; чтение DICOM, подготовка проекций, расчёты и построение поверхностей также используют CPU.

### Несколько пользователей и фоновые задания

Создайте отдельные учётные записи:

```powershell
docker compose exec api python -m sudweb.manage user doctor01
docker compose exec api python -m sudweb.manage password doctor01
docker compose exec api python -m sudweb.manage disable doctor01
docker compose exec api python -m sudweb.manage sessions-prune
```

Пароль запрашивается в терминале, в командной строке не передаётся; минимум 12 символов. Самостоятельная регистрация управляется настройкой выше. Замена пароля и отключение пользователя отзывают его сессии. Bootstrap-пароль применяется только при создании первого аккаунта; редактирование `.env` не меняет пароль существующего пользователя.

Пользователи могут одновременно загружать архивы и просматривать свои результаты. Один worker последовательно обрабатывает задания; API продолжает отвечать, пока идут тяжёлые расчёты. Для параллельных CPU-расчётов:

```powershell
docker compose up -d --scale worker=2
```

Два worker могут потребовать до 24 ГиБ RAM, помимо API, PostgreSQL и ОС. Не масштабируйте GPU-вариант этой командой на одну карту. Каждый worker берёт следующее задание через блокировку строки PostgreSQL `FOR UPDATE SKIP LOCKED`. Повторная обработка после аварии не запускается автоматически в том же каталоге: просроченное задание помечается ошибкой, пользователь загружает архив повторно.

## Как работать

1. Войдите под своей учётной записью. В разделе **«Исследования»** выберите ZIP-архив с DICOM. Можно перетащить файл на область загрузки. Поддерживается ZIP без пароля; RAR/7z и архивы внутри архивов не распаковываются. Сохраните исходную структуру и `DICOMDIR`, если он имеется.
2. Дождитесь статуса **«Готово»**. В карточке видны стадия и прогресс. Страницу можно закрыть: очередь и результаты хранятся на сервере. Доступна отмена ожидающего или выполняющегося задания.
3. Нажмите **«Открыть»**. При нескольких подходящих сериях выберите нужную в верхней строке. ID пациента, дата исследования и описание серии читаются из DICOM. Автоматический выбор предпочитает серии с признаками native; это совпадает с текущей настольной логикой и не является подтверждением отсутствия контраста.
4. В разделе **«Изображения и детекции»** переключайте аксиальную и корональную проекции. Детекция выполняется на корональных изображениях — именно для них обучена модель. Аксиальные доступны для просмотра. Слои отсортированы численно по номеру, а не как строки. Переключатель «Только с детекциями» оставляет изображения с принятыми моделью объектами.
5. Масштабируйте колесом или кнопками, перемещайте изображение мышью. Координаты отсчитываются от левого нижнего угла изображения в миллиметрах. Сетка при исходном масштабе — 5 мм, при увеличении — 1 мм; шкала адаптирует частоту подписей, чтобы они не перекрывались. Под изображением указаны его полный размер и размер видимой части. Пространственный шаг берётся из геометрических sidecar-файлов экспорта.
6. В разделе **«Параметры и 3D»** выберите почку и камень. Здесь показаны размеры, объём, масса, плотность, HU и номера слоёв, а также рисунки, полученные исходным модулем расчёта. Сетка просмотра КТ на эти рисунки не накладывается.
7. Нажмите **«3D камня»**, **«Срез 15%»** или **«3D почки и HU >160»**. Модель можно вращать, перемещать и увеличивать средствами Plotly. Размеры по всем осям — в миллиметрах, пропорции физические. Для почки используются облегчённая розовая оболочка ROI и отдельная поверхность плотных участков HU >160. Оболочка приблизительная, не анатомическая сегментация. Облегчение поверхностей влияет только на отображение; параметры считаются по исходным вокселям.

Начальный ракурс соответствует корональному снимку: X вправо, Z вверх, Y в глубину.
Преобразование учитывает, что сохранённые массивы анализа идут по строкам снимка
сверху вниз; сами HU-массивы и расчётные параметры не изменяются.

После обновления версии с исправленной ориентацией обновите сохранённые 3D-модели
и их иллюстрации у завершённых заданий (без повторного чтения DICOM и детекции):

```powershell
docker compose exec -e PYTHONPATH=/opt/sud/Application/src:/opt/sud/Web_app/backend worker python -m sudweb.refresh_visuals
```

Команда заменяет только производные JSON-модели и иллюстрации HU/плотности.
Сохранённые PDF сохраняют прежний вид; новые отчёты создаются с исправленной
ориентацией после нового расчёта. Во время обновления оставьте браузерный просмотр
закрытым; после завершения заново откройте результат.
8. В разделе **«Время разрушения»** показана таблица для камня, выбранного в предыдущем разделе. Цвет каждой ячейки, название режима и легенда совпадают с PDF. Наведите мышь, переведите фокус клавиатурой либо нажмите ячейку для подсказки. Используется исходная формула приложения; интерфейс не добавляет неподтверждённые единицы времени или новые критерии режимов.
9. Нажмите **«Скачать PDF»** в верхней строке. Отчёт формируется отдельно для выбранной серии. После завершения работы используйте **«Выйти из системы»**. Пользовательское удаление скрывает карточку; администратор отдельно архивирует ZIP и удаляет результаты, как описано выше.

Если исходный расчёт не может сформировать ROI из детекций почек, результат открывается с явным предупреждением: доступны изображения и детекции, расчёт и PDF недоступны. Это не трактуется как отсутствие камней. Другие ошибки обработки показываются в карточке; подробности доступны администратору в журнале задания. Техническая успешность обработки не подтверждает клиническую точность модели.

### Изоляция и хранение

Внутри Docker данные находятся в именованном томе `studies`:

```text
/data/users/<UUID пользователя>/jobs/<UUID задания>/
├── input.zip
├── input/                     # распакованные файлы только этого задания
├── export/<PatientID>/<StudyDate>/V001/
│   ├── images/{axial,coronal}/
│   ├── geometry/              # физические координаты и шаги
│   └── volume/                # HU-массивы
├── runtime/                   # собственные настройки YOLO/Matplotlib
├── result.json                # внутренний манифест результатов
├── progress.json
└── worker.log
```

Изолируется **UUID задания**, поэтому одинаковые ID пациентов и имена архивов не пересекаются. Изображения, сетки, предпросмотры и PDF доступны владельцу нескрытого исследования либо администратору; архивы исходных ZIP — только администратору. Том данных не опубликован статическим веб-каталогом. API не принимает произвольные файловые пути. Сессионные токены хранятся в БД в виде SHA-256, cookie имеет HttpOnly/SameSite, изменения требуют CSRF-токен. Файлы ZIP проверяются на выход из каталога, ссылки, специальные и повторяющиеся пути, число файлов и суммарный размер. Никакие загруженные pickle, Python-код и веса не исполняются; используются только модель и модули из установки сервера.

Каждое задание выполняется новым Python-процессом. Это важно: исходный расчёт использует глобальное состояние и Matplotlib. Кэш, каталоги, параметры YOLO и настройки шрифтов не разделяются между исследованиями. Отмена завершает процесс; состояние очереди переживает перезапуск API. Потеря heartbeat worker обнаруживается по lease (90 секунд).

По умолчанию: ZIP до 2 ГиБ, распаковка до 8 ГиБ и 20 000 записей, до 8 подходящих серий, до 300 млн вокселей на серию; время задания до часа. Compose допускает 3 активных и 30 сохранённых заданий на пользователя. Worker периодически контролирует объём задания (16 ГиБ) и пользовательских данных (40 ГиБ); это контроль с интервалом, не файловая квота ОС. Меняйте пределы через переменные в [compose.yaml](./compose.yaml), учитывая память и диск. Автоматического удаления готовых исследований нет.

Обученные веса подключаются worker только для чтения из [Application/weights](../Application/weights/). При обновлении модели сохраните совместимость шести классов и YOLO26 end-to-end головы. Перезапустите worker; уже полученные результаты остаются прежними.

## Доступ с других компьютеров

Для серверного использования установите HTTPS reverse proxy (например, nginx или Caddy). API по умолчанию слушает только loopback. Настройте в `.env`:

```dotenv
SUD_PUBLIC_ORIGIN=https://sud.example.org
SUD_SECURE_COOKIE=true
SUD_BIND=127.0.0.1
```

Проксируйте на `http://127.0.0.1:8080`, сохраняйте Host и не включайте буферизацию upload на диске без контроля доступа. Если proxy сам работает в Docker, подключите его к сети этого Compose и проксируйте на `api:8080`; прямую публикацию API можно убрать. Для зашифрованных блоков лимит тела запроса proxy должен быть не менее 1 МиБ + 16 байт (например, `client_max_body_size 2m` в nginx). Каждый блок идёт отдельным запросом; полный размер ZIP ограничивает API. Внешний доступ к PostgreSQL и томам не нужен. Порт 8080, привязанный к `127.0.0.1`, не доступен извне непосредственно.

В конфигурации FastAPI не включено доверие произвольным forwarded-заголовкам. При reverse proxy ограничитель входа по IP видит сам proxy; ограничение по аккаунту сохраняется. Внешнее ограничение запросов по реальному клиентскому IP настраивается на доверенном proxy. Не включайте кэширование `/api/` и не публикуйте журналы/каталоги пациентов. Для реального размещения отдельно настройте резервное копирование, сроки хранения, права доступа и правила работы с персональными данными организации.

## Обслуживание

```powershell
docker compose logs --tail=100 api worker
docker compose restart worker
docker compose down
docker compose up -d
```

`down` сохраняет тома. **`down -v` удаляет БД и исследования**, поэтому для обычной остановки его не используйте. Для резервной копии согласованно сохраните PostgreSQL (например, `pg_dump`) и том `studies`; на время копирования остановите загрузки и worker. `.env` храните отдельно. При восстановлении необходимы оба тома/дамп и данные: файлов без записей БД или одной БД без файлов недостаточно. Отключение пользователя блокирует HTTP-доступ, но уже запущенное задание само по себе не отменяет — его может завершить worker.

## Локальная разработка и тесты

Python 3.11. Создайте отдельное окружение, установите [requirements-dev.txt](./requirements-dev.txt). Для worker дополнительно нужны PyTorch и зависимости [настольного приложения](../Application/requirements.txt), установленные с его [constraints.txt](../Application/constraints.txt). Окружение настольного приложения изменять не требуется.

Пример PowerShell из этой папки после установки зависимостей:

```powershell
$env:PYTHONPATH = "$PWD/backend"
$env:PYTHONDONTWRITEBYTECODE = '1'
$env:SUD_SECURE_COOKIE = 'false'
python -m sudweb.manage init
python -m sudweb.manage user developer
python -m uvicorn sudweb.api:create_app --factory --host 127.0.0.1 --port 8080 --no-access-log
```

Во втором терминале с теми же переменными и окружением:

```powershell
python -m sudweb.worker
```

Без `DATABASE_URL` используется SQLite в локальной `var` — только для разработки на одном хосте. Для развёртывания и нескольких worker используйте PostgreSQL из Compose. Проверки:

```powershell
$env:PYTHONPATH = "$PWD/backend"
python -m unittest discover -s tests -v
```

Для полного теста нужны общие вычислительные зависимости. Проверка загрузки DICOM на CPU/GPU и контейнерной установки отличается от unit-тестов; фактически выполненные проверки записаны в конце этого документа.

После сборки worker те же тесты можно выполнить в контейнере:

```powershell
docker compose run --rm --no-deps --volume "${PWD}/tests:/opt/sud/Web_app/tests:ro" worker python -m unittest discover -s /opt/sud/Web_app/tests -v
```
